## 6. Identity and curated memory

Project identity is in Git, not in memory: `AGENTS.md` (`e979ffedbb77d429`) is the operating
contract, `PROJECT.md` the definition, `STATE.md` (`9745ecf17e3cb719`) the narrative state, and
`docs/OPERATIONS.md` (`2d2b0535aa894272`) the policy. Memory holds only facts that apply to every
session and have no home in a task skill:

- the coordinator's hardware/limits (≈1.9 GiB RAM, 4 vCPU, one persistent path, no Docker daemon,
  no `gh`/`hcloud`/`jq`/`zip` on PATH);
- the credential convention: secrets arrive through the dashboard `/env` route into
  `/opt/data/.env`; workers read `_FILE` paths; values are never typed into chat;
- that `hermes` is not on PATH and must be invoked as
  `/opt/hermes/.venv/bin/python3 /opt/hermes/hermes`;
- that external-dir skills are read-only to `skill_manage` and must be edited in the repo;
- that pushes use the publish token in the URL with `GH_TOKEN` unset.

## 9. Overlap with scheduled work

The discovery tick runs at 00/04/08/12/16/20 and the advancement tick at 02/06/10/14/18/22; each can
hold `.factory/research-session.lock` for up to 90 minutes. This handoff made **no** repository
changes on `main` and launched nothing, so it cannot collide. Anything that edits `candidates/`,
`release/` or `STATE.md` on `main` can collide with either tick — the branch isolation here is
deliberate.
